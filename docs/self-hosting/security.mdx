A self-hosted copy of AppBlips is designed to run on your own computer, for a single user. This page explains the security boundaries that matter in that setup, and what to do if other devices can reach it.

## Keep It on Your Own Computer

<Warning>
  A self-hosted copy has **no sign-in**. The builder endpoint (`/api/chat`) and the AI relay for your generated apps (`/api/app-ai/chat`) accept every request as the same local user. **Anyone who can reach them can spend your API key.**
</Warning>

- `npm run dev` and the Docker setup are meant to be opened at `localhost`. The Docker Compose file binds to `127.0.0.1` for this reason.
- If you do make AppBlips reachable from other devices on your network, put your own access control in front of it, such as a firewall rule or a VPN.
- Set a spend limit with your AI provider. AppBlips' built-in rate limits are in-memory speed bumps that reset on restart, not billing caps.

## Your API Key

Your provider key lives only in `.env` and is used only by the AppBlips server. It is never sent to the browser, never embedded in generated app code, and never included in exported HTML. In relay mode, exported apps contain only the relay URL.

## Sandboxed Preview

Generated apps never run directly inside the main AppBlips page. Every generated app runs in an isolated preview, which means:

- The generated app cannot access the parent page's DOM, cookies, or `localStorage`
- The parent page cannot reach into the generated app's DOM
- The generated app cannot make credentialed requests that carry your AppBlips session

This isolation is the main protection against malicious or buggy generated code affecting AppBlips itself.

## Relay Origins

The AI relay accepts calls only from AppBlips' own origin unless you list others in `APPBLIPS_APP_AI_ALLOWED_ORIGINS`. List only exact origins you control, and add `null` (the origin of `file://` pages) only if you knowingly want any locally opened HTML file to use your key.

## BYOK Key Storage

If you switch to `byok` mode, each person using a generated AI-enabled app enters their own provider endpoint, model, and API key the first time AI is needed:

- The key is stored in the **browser only** — in `sessionStorage` by default, or `localStorage` if the user checks **Remember on this device**
- The key is **never sent to AppBlips**
- The key is **never embedded in the generated HTML** when an app is exported

<Note>
  While a generated app is connected to AI, JavaScript running inside that app can read the key in order to make AI calls. Only enter keys with spend limits or scoped permissions, never shared or high-privilege keys.
</Note>

## Opening Exported Apps

Exported apps are self-contained HTML with full script privileges. Open or host them separately from AppBlips (for example, as a local file or on a different domain) rather than serving them from the same origin as AppBlips, so an app can't read what AppBlips stores in the browser.
