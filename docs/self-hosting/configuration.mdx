<Note>
  Using the [desktop app](/quickstart-desktop)? You don't need any of this: set your AI provider in the app under **Settings → AI**.
</Note>

When you [run from source](/quickstart-self-hosted) or with [Docker](/self-hosting/docker), all configuration lives in one `.env` file in the project folder. Copy `.env.example` to `.env`, fill in an API key and a model, and leave everything else blank to use the defaults. When AppBlips starts, it prints which provider it found and what is still missing. It never prints key values.

<Note>
  The general AI variables used to be named `APPBLIPS_LLM_*` (for example `APPBLIPS_LLM_MODEL`, now `OPENAI_LLM_MODEL`). The old names still work, and AppBlips lists any you still use at startup so you can rename them.
</Note>

## Required: AI Provider

Fill in the API key for **one** provider, plus the model. The provider whose key is filled in becomes active.

<ParamField body="APPBLIPS_OPENAI_API_KEY" type="string">
  OpenAI API key.
</ParamField>

<ParamField body="OPENAI_API_KEY" type="string">
  OpenRouter API key. OpenRouter is the recommended way to reach Claude, Gemini, and most other models with a single key.
</ParamField>

<ParamField body="APPBLIPS_DEEPSEEK_API_KEY" type="string">
  DeepSeek API key.
</ParamField>

<ParamField body="APPBLIPS_ZAI_API_KEY" type="string">
  Z.ai API key (pay-as-you-go).
</ParamField>

<ParamField body="APPBLIPS_ZAI_CODING_API_KEY" type="string">
  Z.ai GLM Coding Plan key. The plan has its own endpoint, and its quota doesn't work with `APPBLIPS_ZAI_API_KEY`, so use this one for a plan key.
</ParamField>

<ParamField body="OPENAI_LLM_MODEL" type="string" required>
  The model to use, written exactly as your provider names it. For example `gpt-5.1` (OpenAI), `anthropic/claude-sonnet-5` or `google/gemini-3-pro` (OpenRouter), `deepseek-chat` (DeepSeek), or `glm-5.3-flash` (Z.ai).
</ParamField>

Keys are read only by the AppBlips server and are never sent to the browser.

### Or set it in the app

You can leave these lines blank and choose a provider, model, and API key in the app instead, under [Settings → AI](/reference/settings#your-own-ai-provider). That setting is stored in your browser only, and it takes priority over `.env` while it's switched on. AppBlips then starts with a warning instead of an error.

### Other OpenAI-compatible services

Any other service that speaks the OpenAI chat-completions API works too: Ollama, vLLM, LM Studio, LiteLLM, Groq, and so on.

<ParamField body="OPENAI_BASE_URL" type="string">
  The service's base URL, for example `http://localhost:11434/v1` for Ollama. If you use one of the named providers above, this instead overrides that provider's default endpoint.
</ParamField>

<ParamField body="OPENAI_API_KEY" type="string">
  The service's API key. Ollama needs none, so put any text. This is also the fallback key for whichever provider is active, so `OPENAI_LLM_PROVIDER=zai` with the key here works. It is not the same as `APPBLIPS_OPENAI_API_KEY`, which is the key for OpenAI itself.
</ParamField>

<ParamField body="OPENAI_LLM_PROVIDER" type="string">
  Chooses the provider explicitly when more than one key is filled in: `openai`, `openrouter`, `deepseek`, `zai`, or `openai-compatible`. Blank means the first key found, in that order.
</ParamField>

## Optional: Limits and Tuning

<ParamField body="OPENAI_LLM_MAX_TOKENS" type="number">
  Maximum length of one builder response, in tokens. Blank means the provider default.
</ParamField>

<ParamField body="OPENAI_LLM_TEMPERATURE" type="number">
  Sampling temperature for the builder. Defaults to `0.2`.
</ParamField>

<ParamField body="OPENAI_LLM_ASK_MAX_TOKENS" type="number">
  Token cap for Ask-mode chat replies only, independent of `OPENAI_LLM_MAX_TOKENS`. Defaults to `8192`.
</ParamField>

<ParamField body="OPENAI_LLM_REASONING_PARAM" type="string">
  How your provider expects the reasoning setting: `reasoning_effort`, `reasoning`, `thinking`, or `omit` (send nothing). Blank uses the provider's usual format. You only need this for an unusual OpenAI-compatible service. How much reasoning is used when building is chosen per user in [Settings](/reference/settings#ai); edits and chat replies always use low reasoning.
</ParamField>

<Note>
  Your own copy of AppBlips doesn't limit how many AI requests you make: you pay your provider directly, so only your provider's limits apply. Set a spend limit with your provider to cap costs.
</Note>

<ParamField body="APPBLIPS_CHAT_ALLOWED_ORIGINS" type="string">
  `/api/chat` refuses browser requests that come from any page other than AppBlips itself, so other websites and the apps you build can't spend your key through it. If you reach AppBlips through a reverse proxy that changes the `Host` header, requests may be refused with "Requests from other sites are not allowed." List the address you open AppBlips at here (comma-separated, exact, for example `https://appblips.mydomain.example`).
</ParamField>

## Debug Panel (optional)

<ParamField body="APPBLIPS_DEBUG_PIN" type="string">
  PIN that unlocks a hidden panel showing the raw AI traffic (<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>). Blank disables the feature.
</ParamField>

<ParamField body="APPBLIPS_DEBUG_PIN_RATE_LIMIT_MAX" type="number">
  Wrong PIN guesses allowed per IP per window. Defaults to `5`.
</ParamField>

<ParamField body="APPBLIPS_DEBUG_PIN_RATE_LIMIT_WINDOW_SECONDS" type="number">
  Window for PIN guesses in seconds. Defaults to `300`.
</ParamField>


## Example `.env` Files

<CodeGroup>
```bash Minimal
# The only two lines you need
APPBLIPS_OPENAI_API_KEY=sk-...
OPENAI_LLM_MODEL=gpt-5.1
```

```bash OpenRouter
OPENAI_API_KEY=sk-or-...
OPENAI_LLM_MODEL=anthropic/claude-sonnet-5
```

```bash Ollama (local model)
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_API_KEY=ollama
OPENAI_LLM_MODEL=llama3.1
```
</CodeGroup>
