All configuration for a self-hosted copy of AppBlips lives in one `.env` file in the project folder. Copy `.env.example` to `.env`, fill in an API key and a model, and leave everything else blank to use the defaults. When AppBlips starts, it prints which provider it found and what is still missing. It never prints key values.

## Required: AI Provider

Fill in the API key for **one** provider, plus the model. The provider whose key is filled in becomes active.

<ParamField body="APPBLIPS_OPENAI_API_KEY" type="string">
  OpenAI API key.
</ParamField>

<ParamField body="APPBLIPS_OPENROUTER_API_KEY" type="string">
  OpenRouter API key. OpenRouter is the recommended way to reach Claude, Gemini, and most other models with a single key.
</ParamField>

<ParamField body="APPBLIPS_DEEPSEEK_API_KEY" type="string">
  DeepSeek API key.
</ParamField>

<ParamField body="APPBLIPS_ZAI_API_KEY" type="string">
  Z.ai API key.
</ParamField>

<ParamField body="APPBLIPS_LLM_MODEL" type="string" required>
  The model to use, written exactly as your provider names it. For example `gpt-5.1` (OpenAI), `anthropic/claude-sonnet-5` or `google/gemini-3-pro` (OpenRouter), `deepseek-chat` (DeepSeek), or `glm-5.3-flash` (Z.ai).
</ParamField>

Keys are read only by the AppBlips server and are never sent to the browser.

### Other OpenAI-compatible services

Any other service that speaks the OpenAI chat-completions API works too: Ollama, vLLM, LM Studio, LiteLLM, Groq, and so on.

<ParamField body="APPBLIPS_LLM_BASE_URL" type="string">
  The service's base URL, for example `http://localhost:11434/v1` for Ollama. If you use one of the named providers above, this instead overrides that provider's default endpoint.
</ParamField>

<ParamField body="APPBLIPS_LLM_API_KEY" type="string">
  The service's API key. Ollama needs none, so put any text.
</ParamField>

<ParamField body="APPBLIPS_LLM_PROVIDER" type="string">
  Chooses the provider explicitly when more than one key is filled in: `openai`, `openrouter`, `deepseek`, `zai`, or `openai-compatible`. Blank means the first key found, in that order.
</ParamField>

## Optional: Limits and Tuning

<ParamField body="APPBLIPS_LLM_MAX_TOKENS" type="number">
  Maximum length of one builder response, in tokens. Blank means the provider default.
</ParamField>

<ParamField body="APPBLIPS_LLM_TEMPERATURE" type="number">
  Sampling temperature for the builder. Defaults to `0.2`.
</ParamField>

<ParamField body="APPBLIPS_LLM_ASK_MAX_TOKENS" type="number">
  Token cap for Ask-mode chat replies only, independent of `APPBLIPS_LLM_MAX_TOKENS`. Defaults to `8192`.
</ParamField>

<ParamField body="APPBLIPS_LLM_REASONING_PARAM" type="string">
  How your provider expects the reasoning setting: `reasoning_effort`, `reasoning`, `thinking`, or `omit` (send nothing). Blank uses the provider's usual format. You only need this for an unusual OpenAI-compatible service. How much reasoning is used when building is chosen per user in [Settings](/reference/settings#ai); edits and chat replies always use low reasoning.
</ParamField>

<ParamField body="APPBLIPS_CHAT_RATE_LIMIT_MAX" type="number">
  Requests allowed per window on `/api/chat`. Defaults to `60`.
</ParamField>

<ParamField body="APPBLIPS_CHAT_RATE_LIMIT_WINDOW_SECONDS" type="number">
  Length of the rate-limit window in seconds. Defaults to `300`.
</ParamField>

<Note>
  Rate-limit counts are kept in memory and reset when AppBlips restarts. They guard against accidental runaway usage, not as a billing cap. Set a spend limit with your provider as well.
</Note>

## AI Inside Your Apps

Apps you build with the **AI** switch on call `blip.ai.text(...)`. They always use the **same provider, key, and model** as the builder, through your own AppBlips (unless you switch to BYOK). There is nothing to configure. See [Relay Mode](/ai/relay-mode) and [BYOK Mode](/ai/byok-mode).

<ParamField body="APPBLIPS_GENERATED_AI_MODE" type="string">
  - `relay` *(default, or blank)* — apps call your AppBlips at `/api/app-ai/chat`, which uses your provider.
  - `byok` — each person using a finished app enters their own endpoint, model, and key inside that app.
</ParamField>

<ParamField body="APPBLIPS_APP_AI_RELAY_URL" type="string">
  URL that generated apps call for AI. Defaults to `/api/app-ai/chat` on your AppBlips; exported apps get it as a full address automatically. Change it only if your relay lives at a different address.
</ParamField>

<Warning>
  `APPBLIPS_GENERATED_AI_MODE` and `APPBLIPS_APP_AI_RELAY_URL` are baked into the client at build time. After changing either one, restart `npm run dev`, or run `docker compose up --build` with Docker.
</Warning>

### App AI limits

Generated apps always share the builder's provider, key, endpoint, and model; there is no separate key to configure. Only these limits are separate, and they are never inherited from the builder.

<ParamField body="APPBLIPS_APP_AI_MAX_TOKENS" type="number">
  Maximum tokens per response. Defaults to `4096`.
</ParamField>

<ParamField body="APPBLIPS_APP_AI_TEMPERATURE" type="number">
  Sampling temperature. Defaults to `0.2`.
</ParamField>

<ParamField body="APPBLIPS_APP_AI_REASONING_EFFORT" type="string">
  Reasoning effort for generated-app AI, for example `none` or `low`. Defaults to `none` (off).
</ParamField>

<ParamField body="APPBLIPS_APP_AI_ALLOWED_ORIGINS" type="string">
  Other origins allowed to call the relay, comma-separated and exact. Same-origin callers are always allowed. Add `null` only if you knowingly want local `file://` pages to use your key.
</ParamField>

<ParamField body="APPBLIPS_APP_AI_RATE_LIMIT_MAX" type="number">
  Relay requests allowed per client IP per window. Defaults to `20`.
</ParamField>

<ParamField body="APPBLIPS_APP_AI_RATE_LIMIT_WINDOW_SECONDS" type="number">
  Relay rate-limit window in seconds. Defaults to `60`.
</ParamField>

## Debug Panel (optional)

<ParamField body="APPBLIPS_DEBUG_PIN" type="string">
  PIN that unlocks a hidden panel showing the raw AI traffic (<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>). Blank disables the feature.
</ParamField>

<ParamField body="APPBLIPS_DEBUG_PIN_RATE_LIMIT_MAX" type="number">
  Wrong PIN guesses allowed per IP per window. Defaults to `5`.
</ParamField>

<ParamField body="APPBLIPS_DEBUG_PIN_RATE_LIMIT_WINDOW_SECONDS" type="number">
  Window for PIN guesses in seconds. Defaults to `300`.
</ParamField>

## About Hosted Mode

The repository also contains the hosted mode that runs [appblips.com](https://appblips.com): Firebase sign-in, cloud projects, and public deploys, switched on with `SELF_HOSTED_MODE=false`. It is there because appblips.com is built from this repository. It is not a supported self-hosting setup, and the Elastic License 2.0 does not permit offering AppBlips to other people as a hosted service. Leave `SELF_HOSTED_MODE` unset.

## Example `.env` Files

<CodeGroup>
```bash Minimal
# The only two lines you need
APPBLIPS_OPENAI_API_KEY=sk-...
APPBLIPS_LLM_MODEL=gpt-5.1
```

```bash OpenRouter
APPBLIPS_OPENROUTER_API_KEY=sk-or-...
APPBLIPS_LLM_MODEL=anthropic/claude-sonnet-5
```

```bash Ollama (local model)
APPBLIPS_LLM_BASE_URL=http://localhost:11434/v1
APPBLIPS_LLM_API_KEY=ollama
APPBLIPS_LLM_MODEL=llama3.1
```

```bash BYOK for app AI
APPBLIPS_OPENAI_API_KEY=sk-...
APPBLIPS_LLM_MODEL=gpt-5.1

# People using your finished apps bring their own key
APPBLIPS_GENERATED_AI_MODE=byok
```
</CodeGroup>
