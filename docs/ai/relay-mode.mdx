Relay mode is the default for self-hosted AppBlips. When an AI-enabled app calls `blip.ai.text()`, the request goes to your own AppBlips, which forwards it to your AI provider using the key in your `.env`. No credential dialog appears, and no provider key is ever embedded in the generated HTML.

<Note>
  This page is about self-hosted copies. On [appblips.com](https://appblips.com), AI in your apps is provided by the platform with nothing to configure.
</Note>

## How Relay Mode Works

Every `blip.ai.text()` call inside a generated app sends a request to the relay endpoint (`/api/app-ai/chat` by default). AppBlips forwards it to your provider and streams the response back to the app.

The generated HTML embeds only the relay URL — not the key itself. This means:

- You never enter or handle a provider key inside the app.
- Exporting an app as HTML is safe; the file contains a URL, not a secret.
- The model is the builder's, set in `.env`; change it there without regenerating any apps.

## Setup

There is nothing to set up. Generated apps always use **exactly the same provider, key, and model as the builder** — whatever you filled in during the [quickstart](/quickstart-self-hosted). Change the builder's provider or model and your apps follow.

Only the limits for generated-app AI are separate from the builder. Blank values mean 4096 tokens, temperature `0.2`, and reasoning off:

```bash
APPBLIPS_APP_AI_MAX_TOKENS=
APPBLIPS_APP_AI_TEMPERATURE=
APPBLIPS_APP_AI_REASONING_EFFORT=none
```

## Using Exported Files

The preview and **Open in new tab** work with no changes. Exported files contain the full address of your AppBlips relay (for example `http://localhost:5175/api/app-ai/chat`), so they know where to send AI calls. AppBlips must be running when the app is used.

The relay only accepts calls from AppBlips' own origin by default. A downloaded HTML file opened from somewhere else, such as a `file://` page or another local server, also needs that page's origin listed in `APPBLIPS_APP_AI_ALLOWED_ORIGINS` (comma-separated, exact). Add `null` only if you knowingly want `file://` pages to use your key.

<Warning>
  `APPBLIPS_GENERATED_AI_MODE` and `APPBLIPS_APP_AI_RELAY_URL` are baked into the client at build time. After changing either one, restart `npm run dev`, or run `docker compose up --build` if you use Docker. A plain container restart is not enough.
</Warning>

## Rate Limiting

The relay includes a built-in per-IP rate limiter to catch runaway loops in a generated app:

```bash
APPBLIPS_APP_AI_RATE_LIMIT_MAX=20
APPBLIPS_APP_AI_RATE_LIMIT_WINDOW_SECONDS=60
```

The defaults are 20 requests per 60 seconds per IP address. Requests over the limit receive a `429` response, which `blip.ai.text()` surfaces as a `rate_limited` error.

<Warning>
  The relay spends your provider key and has no sign-in. Keep AppBlips on your own computer. The rate limiter is an in-memory speed bump that resets on restart, not a billing boundary, so also set a spend limit with your AI provider.
</Warning>

## Relay vs BYOK

| | Relay (default) | BYOK |
|---|---|---|
| Someone enters a key in the app | No | Yes — on the first AI call |
| Whose key pays for AI | Yours, from `.env` | The person using the app |
| Key in exported HTML | No — only the relay URL | No |
| Extra configuration | None | `APPBLIPS_GENERATED_AI_MODE=byok` |
