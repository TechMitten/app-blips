Most AppBlips issues fall into a handful of categories — preview rendering and API connectivity. Work through the section that matches your symptom to find a fix.

## Preview Shows a Blank Screen

<AccordionGroup>
  <Accordion title="The preview is blank after generation">
    A blank preview after a successful generation usually means the generated code contains a syntax or runtime error that prevents it from rendering.

    **Steps to fix:**

    1. Open your browser's developer tools and check the **Console** tab for error messages.
    2. Look for JavaScript errors or references to undefined variables.
    3. In the AppBlips prompt input, type a follow-up like `Fix any JavaScript errors` and let AppBlips correct the code.
    4. If the problem persists, try rephrasing your original prompt with more specific instructions about the behavior you want.

    <Tip>
      Enabling **Code view** in Settings lets you inspect the raw generated HTML directly in the preview toolbar, which can help you spot issues at a glance.
    </Tip>
  </Accordion>

  <Accordion title="A link in the preview doesn't go anywhere">
    The preview keeps links from navigating the frame away from your app. A link to another page of your website opens that page in the preview, and external links open in a new tab. A link to a page that doesn't exist does nothing.

    If a link should lead somewhere, ask AppBlips to fix it, for example `The "Pricing" link should open the pricing page`. In the App and Game studios, ask for in-app navigation (showing and hiding views) instead of links to other pages.
  </Accordion>
</AccordionGroup>

## API and Build Errors

<AccordionGroup>
  <Accordion title="I get an API error when building">
    An API error during a build almost always points to a misconfigured or invalid AI provider connection.

    **In the desktop app, open Settings → AI and check that:**

    - An API key is filled in, and it is valid and active for your provider
    - The model is a name your provider recognizes and your key has access to

    Click **Test connection** to check the settings.

    Also confirm that your API key has remaining quota and has not been revoked in your provider's dashboard.
  </Accordion>

  <Accordion title="Build hangs and never completes">
    If the build spinner keeps going without producing output, the request likely timed out or the AI provider is responding slowly.

    **Try the following:**

    1. Dismiss the current build and try again.
    2. Check your AI provider's status page for any ongoing outages or elevated latency.
    3. If **Reasoning: building** is set to Low or High in Settings, try switching it to Off. Reasoning takes longer and is more likely to hit timeouts on slower providers.
  </Accordion>

  <Accordion title="Rate limit or &quot;turned the request down&quot; error">
    **On appblips.com:** "You're sending requests too quickly" means you hit the per-account request limit. Wait a few minutes and try again. "The AI service is busy" means the AI service is overloaded for a moment. Try again shortly.

    **In the desktop app or a copy you run yourself:** AppBlips sets no request limit of its own. An error such as "OpenRouter turned the request down: …" comes from your AI provider, and the text after the colon is the provider's reason. Common causes:

    - **No credit left** on your provider account. Many providers report this as a rate limit (HTTP 429).
    - **The provider's own rate or concurrency limits.** Wait and try again, or check your plan's limits.
  </Accordion>
</AccordionGroup>
