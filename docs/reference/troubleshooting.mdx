Most AppBlips issues fall into a handful of categories — installation, running from source or Docker, preview rendering, and API connectivity. Work through the section that matches your symptom to find a fix.

## Windows installer is blocked

<AccordionGroup>
  <Accordion title="Smart App Control blocked the installer">
    Windows 11's **Smart App Control** blocks apps that aren't code-signed, and it has no "Run anyway" option. AppBlips isn't code-signed yet, so Smart App Control can block the Windows installer or the app itself.

    This only affects machines with Smart App Control turned on — most often fresh Windows 11 installs. If you don't see the block, nothing is wrong.

    **To install AppBlips, turn Smart App Control off:**

    1. Open **Settings → Privacy & security → Windows Security → App & browser control**.
    2. Under **Smart App Control**, select **Smart App Control settings**.
    3. Set it to **Off**, then open the installer again.

    <Warning>
      Smart App Control is a security feature, so turn it off only if you understand the tradeoff. On Windows 11 25H2 and later you can turn it back on afterwards; on earlier versions it stays off until you reset Windows.
    </Warning>
  </Accordion>

  <Accordion title="A new version won't install">
    If you already run AppBlips on a machine with Smart App Control on, the built-in updater can't install a new version, because the update installer isn't signed either. Install the new version by hand after turning Smart App Control off, as above.
  </Accordion>
</AccordionGroup>

<Note>
  The Linux AppImage and `.deb` don't use Smart App Control and are never affected.
</Note>

## Running from source or Docker

<AccordionGroup>
  <Accordion title="&quot;Port 3000 is already in use&quot;">
    Another program is using port 3000.

    - **From source:** start AppBlips on another port. On macOS or Linux run `PORT=3001 npm start`; on Windows (PowerShell) run `$env:PORT=3001; npm start`. Then open `http://localhost:3001`.
    - **Docker:** add `APPBLIPS_PORT=3001` to a `.env` file in the AppBlips folder and run `docker compose up -d` again. See [Use another port](/self-hosting/docker#use-another-port).

    Projects are saved per address, so the new port starts with an empty project list. Export them from **Settings → Data** at the old address first if you need them.
  </Accordion>

  <Accordion title="&quot;This address isn't allowed&quot;">
    AppBlips only answers when you open it as `localhost` or `127.0.0.1`. Open [http://localhost:3000](http://localhost:3000) instead. If you deliberately use another name (for example behind a reverse proxy), add it to `APPBLIPS_ALLOWED_HOSTS` in `.env`. See the [Configuration reference](/self-hosting/configuration#server).
  </Accordion>

  <Accordion title="My projects disappeared">
    The browser version saves projects in your browser, separately for each address. Check that you opened the same address as before (same port, `localhost` rather than `127.0.0.1`), in the same browser and not a private window. Clearing your browser's site data deletes them for good, so back up with **Settings → Data → Export** now and then.
  </Accordion>

  <Accordion title="npm install or npm start fails">
    Check your Node.js version with `node --version`. AppBlips needs 22.12 or newer; install the **LTS** version from [nodejs.org](https://nodejs.org/). Then delete the `node_modules` folder and run `npm install` again.
  </Accordion>

  <Accordion title="npm run desktop on Linux fails with a chrome-sandbox error">
    Ubuntu 24.04 and some other distributions need Electron's sandbox helper to be owned by the system. In the AppBlips folder, run:

    ```bash
    sudo chown root:root node_modules/electron/dist/chrome-sandbox
    sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
    ```

    Then run `npm run desktop` again. Don't use `--no-sandbox` instead.
  </Accordion>

  <Accordion title="Docker can't reach LM Studio or Ollama">
    On Linux, the local server has to accept connections from the container. Start Ollama with `OLLAMA_HOST=0.0.0.0`, or turn on **Serve on Local Network** in LM Studio. If it still fails, a firewall may block the container. See [Local models](/self-hosting/docker#local-models-lm-studio-and-ollama).
  </Accordion>
</AccordionGroup>

## Preview Shows a Blank Screen

<AccordionGroup>
  <Accordion title="The preview is blank after generation">
    A blank preview after a successful generation usually means the generated code contains a syntax or runtime error that prevents it from rendering. AppBlips catches most of these and fixes them on its own, and runs a full review if the quick fixes don't work.

    **If the preview is still blank:**

    1. In the AppBlips prompt input, type a follow-up like `The preview is blank. Fix any JavaScript errors` and let AppBlips correct the code.
    2. Click the camera key next to the prompt box to attach a screenshot of the preview, so the AI can see what you see.
    3. If the problem persists, step back with **Previous version** and try rephrasing your prompt with more specific instructions about the behavior you want.

    <Tip>
      Enabling **Code view** in Settings lets you inspect the raw generated HTML directly in the preview toolbar, which can help you spot issues at a glance.
    </Tip>
  </Accordion>

  <Accordion title="A link in the preview doesn't go anywhere">
    The preview keeps links from navigating the frame away from your app. A link to another page of your website opens that page in the preview, and external links open in a new tab. A link to a page that doesn't exist does nothing.

    If a link should lead somewhere, ask AppBlips to fix it, for example `The "Pricing" link should open the pricing page`. In the App and Game studios, ask for in-app navigation (showing and hiding views) instead of links to other pages.
  </Accordion>
</AccordionGroup>

## API and Build Errors

<AccordionGroup>
  <Accordion title="I get an API error when building">
    An API error during a build almost always points to a misconfigured or invalid AI provider connection.

    **Open Settings → API and check that:**

    - An API key is filled in, and it is valid and active for your provider
    - The model is a name your provider recognizes and your key has access to

    Click **Test connection** to check the settings.

    Also confirm that your API key has remaining quota and has not been revoked in your provider's dashboard.
  </Accordion>

  <Accordion title="Build hangs and never completes">
    If the build spinner keeps going without producing output, the request likely timed out or the AI provider is responding slowly.

    **Try the following:**

    1. Click **Cancel** next to the prompt box and try again.
    2. Check your AI provider's status page for any ongoing outages or elevated latency.
    3. If **Reasoning: building** is set to Low or High in Settings, try switching it to Off. Reasoning takes longer and is more likely to hit timeouts on slower providers.
  </Accordion>

  <Accordion title="The app was cut off or is incomplete">
    Every AI reply has a length limit. When a reply hits it, AppBlips asks the AI to continue where it stopped, up to three times. If the app is still incomplete, the reply says so.

    **Try the following:**

    1. Open **Settings → AI** and look at **Output tokens: building**. If you typed a number there, clear the field to go back to the default of 64,000.
    2. Ask for the rest in a follow-up prompt, for example `Finish the parts that are missing`.
    3. For a very large app, build it in smaller steps: start with the main screen, then add features one prompt at a time.
    4. Some models have a low limit of their own. If this keeps happening, choose a different model in **Settings → API**.
  </Accordion>

  <Accordion title="Rate limit or &quot;turned the request down&quot; error">
    AppBlips sets no request limit of its own. An error such as "OpenRouter turned the request down: …" comes from your AI provider, and the text after the colon is the provider's reason. Common causes:

    - **No credit left** on your provider account. Many providers report this as a rate limit (HTTP 429).
    - **The provider's own rate or concurrency limits.** Wait and try again, or check your plan's limits.
  </Accordion>
</AccordionGroup>
