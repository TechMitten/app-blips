Most AppBlips issues fall into a handful of categories — preview rendering, API connectivity, and Docker setup. Work through the section that matches your symptom to find a fix.

## Preview Shows a Blank Screen

<AccordionGroup>
  <Accordion title="The preview is blank after generation">
    A blank preview after a successful generation usually means the generated code contains a syntax or runtime error that prevents it from rendering.

    **Steps to fix:**

    1. Open your browser's developer tools and check the **Console** tab for error messages.
    2. Look for JavaScript errors or references to undefined variables.
    3. In the AppBlips prompt input, type a follow-up like `Fix any JavaScript errors` and let AppBlips correct the code.
    4. If the problem persists, try rephrasing your original prompt with more specific instructions about the behavior you want.

    <Tip>
      Enabling **Code view** in Settings lets you inspect the raw generated HTML directly in the preview toolbar, which can help you spot issues at a glance.
    </Tip>
  </Accordion>

  <Accordion title="A link in the preview doesn't go anywhere">
    The preview keeps links from navigating the frame away from your app. A link to another page of your website opens that page in the preview, and external links open in a new tab. A link to a page that doesn't exist does nothing.

    If a link should lead somewhere, ask AppBlips to fix it, for example `The "Pricing" link should open the pricing page`. In the App and Game studios, ask for in-app navigation (showing and hiding views) instead of links to other pages.
  </Accordion>
</AccordionGroup>

## API and Build Errors

<AccordionGroup>
  <Accordion title="I get an API error when building">
    An API error during a build almost always points to a misconfigured or invalid AI provider connection.

    **Check the following in your `.env` file:**

    - Exactly one provider key is filled in (for example `APPBLIPS_OPENAI_API_KEY`), or `OPENAI_LLM_PROVIDER` picks one if several are
    - The key is valid and active for that provider
    - `OPENAI_LLM_MODEL` is a model name your provider recognizes and your key has access to
    - For another OpenAI-compatible service, `OPENAI_BASE_URL` is the full base URL (for example `http://localhost:11434/v1`)

    When AppBlips starts, it prints which provider it found and which values are still missing. Check that output first.

    Also confirm that your API key has remaining quota and has not been revoked in your provider's dashboard.
  </Accordion>

  <Accordion title="Build hangs and never completes">
    If the build spinner keeps going without producing output, the request likely timed out or the AI provider is responding slowly.

    **Try the following:**

    1. Dismiss the current build and try again.
    2. Check your AI provider's status page for any ongoing outages or elevated latency.
    3. If **Reasoning: building** is set to High in Settings, try switching it to Low — reasoning takes longer and is more likely to hit timeouts on slower providers.
  </Accordion>

  <Accordion title="Rate limit or &quot;turned the request down&quot; error">
    **On appblips.com:** "You're sending requests too quickly" means you hit the per-account request limit. Wait a few minutes and try again.

    **In the desktop app or a copy you run yourself:** AppBlips sets no request limit of its own. An error such as "Z.ai turned the request down: …" comes from your AI provider, and the text after the colon is the provider's reason. Common causes:

    - **No credit left** on your provider account. Many providers report this as a rate limit (HTTP 429).
    - **A plan key on the wrong endpoint.** A Z.ai GLM Coding Plan key needs the **Z.ai Coding Plan** provider, not **Z.ai**.
    - **The provider's own rate or concurrency limits.** Wait and try again, or check your plan's limits.
  </Accordion>
</AccordionGroup>

## Docker Issues

<AccordionGroup>
  <Accordion title="Port 3000 is already in use">
    AppBlips listens on port 3000 by default. If another process is already using that port, the container will fail to start.

    **To fix:**

    - Stop the process currently occupying port 3000, then run `docker compose up` again.
    - Alternatively, publish AppBlips on another host port: in `docker-compose.yml`, change the first number of the port mapping (for example `"127.0.0.1:8080:3000"`) and open `http://localhost:8080`. See [Ports](/self-hosting/docker#ports).
  </Accordion>

  <Accordion title="Changes to .env don't take effect">
    Docker passes `.env` to the container when it is created, so `docker compose restart` keeps the old values. Recreate the container instead:

    ```bash
    docker compose up
    ```
  </Accordion>
</AccordionGroup>

<Note>
  For questions about initial Docker setup and `.env` configuration, see the [self-hosting guide](/self-hosting/docker). For general questions about how AppBlips works, visit the [FAQ](/reference/faq).
</Note>
