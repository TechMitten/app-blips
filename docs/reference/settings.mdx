The Settings modal — accessible from the header — gives you control over how AppBlips looks and behaves. It is organized into tabs: **Appearance**, **Workspace**, **AI**, **Connectors**, **API**, **Data**, **Legal**, **Licenses**, and **Danger Zone**. Every setting is saved on your device and persists across sessions automatically.

---

## Appearance

These settings control the visual presentation of the AppBlips interface.

### Theme

<ParamField body="Theme" type="Light | Dark | System" default="Dark">
  Sets the color scheme for the AppBlips interface. **Light** keeps the interface in a light palette at all times. **Dark** keeps it dark at all times. **System** follows your operating system's current color scheme preference and switches automatically when your OS switches.
</ParamField>

### Build pane font

<ParamField body="Build pane font" type="Small | Default | Large | XL" default="Small">
  Controls the text size throughout the entire build pane, including starter ideas, the conversation history, and the prompt input field. Increase this if you prefer larger text while writing or reviewing prompts.
</ParamField>

### Build pane position

<ParamField body="Build pane position" type="Left | Right" default="Left">
  Determines which side of the workspace the build pane appears on. This setting applies on wider screens where both the build pane and the preview panel are displayed side by side.
</ParamField>

## Workspace

These settings control how the preview and build experience behaves during and after generation.

### Code view

<ParamField body="Code view" type="toggle" default="Off">
  When enabled, a **Code** tab appears in the preview toolbar. Select it to inspect the raw HTML of your generated app at any time. This setting is off by default so the interface stays focused on the live preview for most users. Imported sites always show a **Files** tab instead, whatever this is set to.
</ParamField>

### Auto Follow Code

<ParamField body="Auto Follow Code" type="toggle" default="On">
  When enabled, the **Code** tab automatically scrolls to keep the most recently written line visible as AppBlips streams in the generated code. Disable this if you want to scroll back and read earlier sections while generation is still in progress.
</ParamField>

### Live code preview

<ParamField body="Live code preview" type="toggle" default="On">
  When enabled, the preview pane shows a live peek at the code being written while your app is generating. Disable this if you prefer a clean preview that only updates once the full app is ready.
</ParamField>

### Skip splash screen

<ParamField body="Skip splash screen" type="toggle" default="Off">
  When enabled, AppBlips never plays the intro animation and takes you straight to the workspace. This setting takes effect on the next page load — the current session is not affected.

  With it off, the intro plays every time AppBlips opens or the page reloads. Click **Skip** in the bottom-right corner, or press <kbd>Esc</kbd>, to skip it.
</ParamField>

### Check for updates

<ParamField body="Check for updates" type="toggle" default="On">
  AppBlips checks GitHub for new versions when it starts and tells you when one is out. The desktop app checks again every hour while it's open. The desktop app on Windows and as an AppImage also downloads the update in the background and offers to restart. If you run AppBlips from source or Docker, it links to [how to update](/quickstart-source#updating). GitHub sees your IP address when AppBlips checks. The [Microsoft Store](/quickstart-desktop#install) version is updated by the Store, so its notice links to the Store page instead. The setting also shows which version you're on, and a change takes effect the next time you open AppBlips.
</ParamField>

### Replay onboarding

Desktop app only. Click **Replay** to see the setup screens again: your name, chat avatar and projects folder, then the AI setup. Your current AI setup is kept unless you save a new one, and you can leave without changing anything.

## AI

These settings influence how the AI model reasons and communicates before and during generation.

### Output tokens

A token is a small piece of text, roughly three-quarters of a word. These limits cap how long one AI reply can be.

<ParamField body="Output tokens: building" type="number" default="64,000">
  The longest reply allowed when building, editing, reviewing or fixing code. Leave it empty to use the default of 64,000, which is enough for a large app (LM Studio and Ollama use their own default instead). Reasoning (thinking) also counts against this limit. If your provider doesn't accept the number, AppBlips retries with the largest value the provider allows.
</ParamField>

<ParamField body="Output tokens: Ask" type="number" default="Provider default">
  The longest reply allowed in Ask mode. Leave it empty to let your AI provider decide.
</ParamField>

Changes save as you type. Click **Use default** (or **Use provider default**) to clear a value.

### Reasoning

Reasoning applies whenever the AI writes code: building a new app, editing one, and fixing errors.

<ParamField body="Reasoning" type="Off | Low | High" default="Low">
  Lets the AI reason before it writes code, for new apps and for changes. **Off** is fastest. **Low** thinks a little first. **High** thinks harder for complex apps but takes longer.
</ParamField>

<Tip>
  Chat-only replies (clarifying questions and Ask-mode answers) always run with reasoning off, so they stay quick.
</Tip>

### Clarifying questions

<ParamField body="Clarifying questions" type="toggle" default="Off">
  When enabled, AppBlips may ask you a clarifying question before generating — for example, to confirm the intended behavior of an ambiguous feature. This helps the AI understand your intent and can reduce back-and-forth editing, but adds a step before the first build begins.
</ParamField>

### Code Review (beta)

<ParamField body="Code Review" type="toggle" default="Off">
  Code Review is a beta feature, so it is off by default. When enabled, AppBlips asks after every build or edit whether anything looks wrong on screen. Choose **Looks wrong** and the AI takes screenshots, tests the project in the built-in browser, reads the code, and writes a report with a screenshot as evidence for each problem. Choose **Looks fine** and it tests the project and reads the code the same way, but without screenshots, which uses fewer tokens. It doesn't change anything itself. If the report lists problems, AppBlips asks whether to fix them. Choose **Fix problems** and a new chat starts with the report as its task, and the AI fixes them as a normal edit, or choose **Not now** to leave things as they are. Choose **Skip** to move on without a review. Reviews can use a lot of extra tokens, so they only run when you say yes. Leave this off to skip both the question and the review.
</ParamField>

### Smart game engine

<ParamField body="Smart game engine" type="toggle" default="On">
  Applies in the Game studio. Before building a new game, the AI picks the engine that suits it: **Phaser** for platformers, shooters and RPGs, **Three.js** for 3D games, and no engine for simple arcade, puzzle and card games, which then load faster. If you name an engine in your prompt, your choice always wins. The chat shows which engine was picked, right after the AI's first sentence. Turn it off to let the builder choose as it writes. See [Game engines](/features/building-apps#game-engines).
</ParamField>

### Smart website add-ons

<ParamField body="Smart website add-ons" type="toggle" default="On">
  Applies in the Website studio. Before building a new website, the AI picks ready-made libraries that suit it: **Swiper** for carousels, **GLightbox** for full-screen photos, **GSAP** or **AOS** for scroll animations, **Lenis** for smooth scrolling, **Alpine.js** for tabs and toggles, **Chart.js** for charts and **Leaflet** for maps. Simple sites get none, so they load faster. If you name a library in your prompt, your choice always wins. The chat shows which add-ons were picked, right after the AI's first sentence. Turn it off to build new websites with plain JavaScript only. See [Website add-ons](/features/building-apps#website-add-ons).
</ParamField>

## Connectors

Connectors link outside services to your projects, so the AI wires them into what it builds. Click a card to set that service up. Each service's page has an **Enable** switch, a box for its key, code or link, a **How it works** button, and **Prompts to try**: ready-made requests to copy into the builder chat. Changes save as you type. See [Connectors](/features/connectors) for step-by-step setup of each service.

When you're signed in to Surge for [Publish to the web](/features/publishing), a **Publishing (Surge)** row below the cards shows your Surge email. Click **Sign out** to forget the sign-in.

<ParamField body="Enable Web3Forms" type="toggle" default="Off">
  Emails your form entries to you. Needs your Web3Forms access key. See [Web3Forms](/features/connectors#web3forms).
</ParamField>

<ParamField body="Enable Umami" type="toggle" default="Off">
  Counts visitors. Needs your Umami tracking code or website ID. See [Umami](/features/connectors#umami).
</ParamField>

<ParamField body="Enable Plausible" type="toggle" default="Off">
  Counts visitors. Needs your Plausible tracking code. See [Plausible](/features/connectors#plausible).
</ParamField>

<ParamField body="Enable tawk.to" type="toggle" default="Off">
  Adds a live chat bubble. Needs your tawk.to widget code. See [tawk.to](/features/connectors#tawkto).
</ParamField>

<ParamField body="Enable Square" type="toggle" default="Off">
  Takes payments. Needs one or more Square payment links. See [Square](/features/connectors#square).
</ParamField>

Missing a service? Click **Request a connector** at the end of the cards.

## API

Choose the AI provider that builds your apps: **Anthropic** (the default), **OpenAI**, **Gemini**, **DeepSeek**, **LM Studio**, **Ollama**, or **OpenRouter**. Your provider is used for building, editing, reviews, and Ask mode.

With **Anthropic**, AppBlips turns on prompt caching automatically, so the repeated parts of a build cost less. See the [FAQ](/reference/faq) for how it works.

<ParamField body="API key" type="string">
  Your key from [Anthropic](https://platform.claude.com/settings/keys), [OpenAI](https://platform.openai.com/api-keys), [Google AI Studio](https://aistudio.google.com/apikey), [DeepSeek](https://platform.deepseek.com/api_keys), or [OpenRouter](https://openrouter.ai/settings/keys). Local servers only need a key if you turned on authentication.
</ParamField>

<ParamField body="Local server URL" type="string">
  Only for LM Studio and Ollama. The address of your local server, ending in `/v1`. Leave it empty to use the usual address.
</ParamField>

<ParamField body="Model" type="select">
  Select a model from your provider's live model list. Enter your API key first for cloud providers; local providers load models from your running server. Click **Refresh models** to reload the list, or type an exact model ID if the list can't load. For OpenAI, use a model that supports tool calling through Chat Completions. For local servers, load a model that supports tool calling.
</ParamField>

Click **Test connection** to check the settings, then **Save**. **Clear** removes the saved provider and key after you confirm. If you leave the tab with unsaved changes, AppBlips asks whether to save or discard them.

<Note>
  In the desktop app, your key is encrypted with your system keychain and only the app's background process uses it. In the browser version (from source or Docker), AppBlips' own server saves it on your computer, never in your browser. It is never stored in your projects. See [Set up your AI provider](/quickstart-desktop#set-up-your-ai-provider) and [Security](/self-hosting/security#your-api-key).
</Note>

## Data

Where projects are stored on your device.

- **Export all apps:** downloads every saved app, its version history and its saved app data as one backup file. Imported sites aren't included: export each one as a `.zip` instead (see [Export the project](/features/importing-sites#export-the-project)).
- **Import apps:** adds apps from a backup file. An app you already have is replaced only if the backup's copy is newer.
- **Projects folder:** desktop app only. Shows where projects are saved. Click **Change…** to pick another folder. The browser version saves projects in your browser instead.

See [Back up or move your projects](/quickstart-desktop#back-up-or-move-your-projects) for moving apps between computers.

## Licenses

Credits for the open source code inside AppBlips.

- **AppBlips:** AppBlips itself is open source under the MIT License. Click **Show license** to read it, or **Source code** to open the project on GitHub.
- **Open source packages:** every open source package that ships inside AppBlips, with its version and license. Click a package to read its full license text and open its website. Type in **Search packages** to find one by name, license or author.
- **Other credits:** the Whisper speech model that voice input uses, the fonts in the interface, Surge (the hosting service **Publish** uses; no Surge code is included), and, in the desktop app, Chromium. Chromium's own list of licenses is in the file `LICENSES.chromium.html` in the AppBlips install folder.

## Danger Zone

<Warning>
  These actions are permanent and cannot be undone.
</Warning>

- **Delete all saved apps:** removes every saved app with its version history.
- **Reset app to factory defaults** (the **Factory Reset** button): clears all data, settings, API keys and projects, signs you out of Surge, and returns AppBlips to the state it was in when you first installed it.
